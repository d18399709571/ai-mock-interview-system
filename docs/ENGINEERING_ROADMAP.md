# 工程化优化与二次开发路线图

## 记录背景

本文件用于长期跟踪智能模拟面试系统的后续工程化建设。

2026-10-15 首次 GitHub 发布准备期间，决定暂时不公开三份历史 GitHub Actions 工作流。

原因不是这些能力不重要，而是原有工作流包含旧项目 Prepwise 配置，尚未适配、启用并验证当前公开仓库。

这属于阶段性发布范围调整，不代表永久放弃 CI/CD。

## 历史工作流文件

以下文件保留在 Windows 本地发布副本和原始项目来源中，首次发布时计划从 Git 暂存区排除。

1. ai-interview-backend/.github/workflows/quick-check.yml
   - 自动检查 Python 代码质量、格式、安全问题及 Docker 配置
   - 后续目标：建立当前项目真正可运行的 CI 流水线

2. ai-interview-backend/.github/workflows/preview-deploy.yml
   - 预览环境测试、Docker 镜像构建、GHCR 推送和 SSH 部署
   - 后续目标：适配当前仓库的预览环境自动部署

3. ai-interview-backend/.github/workflows/production-deploy.yml
   - 生产环境测试、镜像构建、部署、数据库备份和回滚
   - 后续目标：建立安全可靠且经过演练的生产发布流程

## 当前已识别的问题

- 部署工作流仍保留旧项目名称及目录配置。
- 工作流不位于当前 Git 仓库根目录的 .github/workflows/。
- 尚未验证这些工作流能够在新仓库中正确运行。
- 部分测试或备份失败可能不会阻止部署，需要建立严格的失败门禁。
- 需要补充真实可执行的数据库恢复和回滚验证。
- 当前不得声称已完成或验证生产级 CI/CD。

## 实施原则

- 先学习和理解现有实现，再进行改造。
- 只在明确授权后修改项目源代码。
- 不直接修改 Google Drive 原始项目。
- 不将真实密钥、密码及私人部署环境信息公开。
- 所有完成状态必须以真实代码和测试记录为依据。
- 后续每完成一个阶段，更新本文件和 README。

## 跨窗口续接说明

未来继续项目优化时，优先读取：

- README.md
- docs/ENGINEERING_ROADMAP.md
- 需要学习或改造的具体工作流源码

从最近一个未完成的工程化阶段继续，不要将历史工作流误认为已投入运行。

当前优先目标仍是完成首次 GitHub 发布；
CI/CD 适配属于发布后的工程化提升和二次开发任务。
